# 思维工坊

> 一个产品决策工作坊：输入需求 → 需求分析 → AI 产品规划 → 专家团评审交锋 → 最终决策。
> 女娲造出的「人物脑」放 `../skills/personas/`；专家名册在 `committee/`；流程在 `工作流程.md`。

## 从这里开始

1. **读流程** → [`工作流程.md`](工作流程.md)（六阶段 SOP，含资料缺口协议与启动指令）
2. **点专家** → [`committee/README.md`](committee/README.md)（产品大师 + 职能专家 + 用户代表 + 成本中心）
3. **拿模板** → [`templates/`](templates/)（00-需求输入 … 06-复盘记录）
4. **开会** → 产出归档到 [`sessions/`](sessions/)（每场一个日期目录）

## 目录结构

```
workshop/
├── 工作流程.md              # ★ 主流程 SOP（先读这个）
├── committee/               # 专家名册
│   ├── README.md            #   名册总览
│   ├── personas/            #   产品大师（乔布斯✅/张小龙✅/雷军✅）
│   └── roles/               #   职能专家（商业/技术/体验/增长）+ 用户代表 + 成本中心
├── templates/               # 00~06 阶段模板
└── sessions/                # 每场工坊产出（本地归档；案例默认不入库，见根 .gitignore）
```

## 快速开始

把这条指令发给 AI，替换需求即可：

```
进入产品思维工坊，执行标准工作流程：
1. 读取 workshop/工作流程.md，按六阶段执行；
2. 读取 workshop/committee/README.md 点专家团；
3. 产物写入 workshop/sessions/<今天日期>-<主题>/ 对应文件；
4. 需要资料时按「资料缺口协议」处理（问用户→搜电脑文档→联网检索）；
5. 我的需求是：<粘贴原始需求>
```

## 纪律速览

- 阶段 0-5 每步必须落盘对应文件（口头聊完 = 没开会）。
- 专家先独立发言、后交锋；必须答「绝不会怎么做」；标盲区。
- 决策权在用户 —— 委员是顾问，AI 是主持与记录。
